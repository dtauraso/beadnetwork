Link Rules Check

The editor draws nodes moving as links are stepped. A drawing can be faked, so this page sets the drawing aside. It takes the numbers the editor saved and recomputes every position from seven written rules. The checking code in rules/ is its own, written from the rules, and none of it comes from the editor. All of it is shown at the bottom of the page.

Everything in data/ comes from the editor's Go code, run outside the editor by scripts/readscene. The loaded data is the export of all six sequences, taken on 2026-10-31 with go run ./scripts/readscene -json topology-pair-phi-theta-3 and kept in data/scene-export.js. Edit any number, or paste your own export, and press Check.

The rules

For a link, s is the s of the node it goes to, and one turn is T = 12·s ticks.

  1. Where a link points. φ = start φ + Δφ and θ = start θ + Δθ, each wrapped into 0 ≤ angle < T. r = start r + Δr.
    The code for this rule
    2. 
      
  2. A step. It adds the increment, plus or minus, to one Δ (φ, θ or r), or with the "both" button to all three, and changes nothing else in that link. An angle's Δ is wrapped into 0 ≤ Δ < T; Δr is not. A step that would take r below 0 is refused.
        
    The code for this rule
    3. 
      
  3. A link's vector. With a(t) = t · 2π / T:
        x = r·ρ·sin a(φ)·cos a(θ)
y = r·ρ·cos a(φ)
z = r·ρ·sin a(φ)·sin a(θ)
        One case differs: when φ > T/2 and φ = θ, z is negated. There both angles count as negative, and without the flip sin φ · sin θ would be a square that never lets the link reach the negative-z side.
        
    The code for this rule
    4. 
      
  4. A node's position. The same formula, with r · constant-r for the length, φ · 2π / max-index-φ and θ · 2π / max-index-θ for the angles, and no z flip.
        
    The code for this rule
    5. 
      
  5. Every link closes. For every link a→b, position(a) + vector(a→b) = position(b), to floating-point rounding.
        
    The code for this rule
    6. 
      
  6. What a press changes. A press steps one link into each node: the first selected one, in saved order. That link's Δ changes as rule 2 says and its start stays. No other link's Δ changes. A node reached by a stepped link moves to position(from) + vector(link) with the new Δ; every other node stays where it was. The page predicts After from Before this way and compares the prediction with what the editor's code recorded.
        
    The code for this rule
    7. 
      
  7. The order of presses does not change Δ. Steps add whole-number increments to Δ, and addition does not depend on order, so φ+, θ+ and r+ in any of their six orders leave every link with the same Δ. A link that was not stepped can get a new start, worked out again from where the nodes moved to; that never changes its Δ.

Rules 1–5 are checked on one state. Rule 6 needs a before and an after. data/scene-steps.js holds 48 of them: each of the eight step buttons pressed once on each sequence, made with go run ./scripts/readscene -steps topology-pair-phi-theta-3. Rule 7 uses data/scene-orders.js, made with -orders: the six orders of φ+, θ+ and r+ on every sequence. Both files start in the Runs box below, where every run is checked against rule 6 and every group of runs pressing the same buttons in different orders against rule 7. Any run can be edited there, or replaced with your own -steps or -orders output, and any one can be loaded into Before and After.
