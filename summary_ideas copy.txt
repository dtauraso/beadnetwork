describe how does it work
There is a 3d simuliation system.
It uses local integer changes to angles to do 3d rotations.

paragraphs version:
The software is a 3D simulation system.
It does 3D rotations by making small integer changes to angles,
and it makes those changes locally:
each part holds its own polar coordinates,
and that local data is the truth the system runs on.
Integers are the main control numbers,
so a rotation is a count of steps rather than an arbitrary decimal value.

The global picture is a projection of that local data.
A local-to-global adaptor builds global positions from the local parts
so they can be drawn on the screen.
The adaptor exists so the local system can be seen, and tested, on screen.

Going the other way, global positions are turned back into local vectors
for the links that are not selected:
when a node moves, each unselected link is remeasured from the two nodes' places.
Those rebuilt local values are allowed to be floats,
because they are not part of the control system.
The selected links keep their integer steps.

A UI sits on top of this
for setting the angles and the many other settings
that control the 3D rotations.

Each link holds its own polar start (φ, θ, r)
and its own Δ, which changes only in integer steps.
A selected link is the truth for where its node goes:
the node is placed from the other node's place plus that link.
An unselected link goes the other way:
it is rebuilt from the two nodes' places, as floats.
The floats are only the base a link's Δ steps from,
so the link always matches where its two nodes really are,
while every change the user makes is still a whole step of Δ.

Each node runs on its own goroutine
and owns the links that come in to it.
A step starts when the UI sends it to every node.
After that the nodes settle it themselves,
by sending their places to their neighbours,
and each one waits until it has heard from all of its neighbours.

All nodes count time from one shared clock,
each holding its own copy,
and the tick length is set from the UI,
so a change happens in steps that can be watched on the screen
instead of all at once.

The simulation owns all of the geometry.
The screen only draws what the simulation writes out,
so what is shown is the simulation's own state,
not a second copy that could disagree with it.
