describe how does it work
There is a 3d simuliation system.
It uses local integer changes to angles to do 3d rotations.
It has a ui for setting angles and many other settings for 3d rotations.

paragraphs version:

the parts:
The software is a 3D simulation system.
It is a network of nodes joined by links.
Each link is held by the node it goes into,
and holds its own polar start (φ, θ, r)
and an integer Δ on top of it, one for each of φ, θ and r.

steps:
Angles are counted in ticks:
a whole turn is 12 × s ticks, where s is the node's own scale.
Integers are the main control numbers,
so a rotation is a count of steps rather than an arbitrary decimal value.
Each press moves Δ by the link's whole-number increment.

two angles:
A link's direction is worked out from its start plus its Δφ and Δθ,
each added on its own,
and turned into x, y, z once, from the totals.
No step is applied on top of another step,
so the order the steps were made in never reaches the result.

moving nodes:
Each node keeps a global place,
which is polar too (r, φ, θ around the scene's centre),
held as floats and saved to a file.
A local-to-global adaptor turns places and links into x, y, z.
A stepped link places its node:
the node goes to the other node's place plus the link.
The adaptor was picked so the local system can be seen, and tested, on screen.

Going the other way, global places are turned back into local links.
When a node moves, its links that did not move it
are remeasured from the two nodes' places,
and its neighbours remeasure the links from it into them.
Only a link's start is rebuilt, as floats,
because the start is not part of the control system;
its Δ stays a whole number of steps.
While the selected links are stepped together, they are kept, not remeasured.
When one link is edited on its own, that link places its node,
and every other link at the node is remeasured, selected or not.

the network:
Each node runs on its own goroutine, with its own inbox.
A step of all the selected links starts when the UI sends it to every node,
numbered as a round.
A node whose selected link was stepped
waits for the place of the node that link starts from,
then places itself from that place plus the link.
Each node sends its new place to its neighbours,
and shows the step only once it has heard that round from all of them.
Each node checks its own links' changes,
and refuses a length below zero
or a second selected link into itself.

time:
Every node counts ticks from one shared clock, each with its own copy.
The tick length is set from the UI,
and a step is shown a couple of ticks after it is sent.

sequences:
Each sequence is its own folder of nodes and links,
one value per file.

the screen:
The simulation writes each place, each link and everything drawn to files,
one writer per file.
The screen reads those files and draws them;
it works out no positions of its own.
A UI sits on top of this
for setting the angles and the many other settings
that control the 3D rotations.

the tools:
It is built only from tools in everyday use:
polar coordinates, whole-number counting, addition,
sin and cos and their inverses, subtracting one point from another,
nodes passing messages, and a clock.

the parts:
It is a network of nodes joined by links.
Each link goes from one node to another
and holds a direction, φ and θ, and a length, r.
Each node holds the links that come into it.
to see it: open the Links pill, the table of every link;
each row is one link a→b with its φ, θ and r.
to read it: Categories/Node/Links/link.go, type Link: From, To, Start (φ, θ, r), Delta, Increment.

steps:
It rotates links in 3D by steps.
Each link has a change added to each of its two angles and its length:
Δφ is the change added to φ, Δθ the change added to θ, and Δr the change added to r.
Each one is a whole number of steps.
Stepping one back the same number of times returns it to exactly where it was.
However many steps are made, forward and back,
it never drifts away from the count of steps that were made.
to see it: press a link's step up button (▲) and then its step down button (▼)
the same number of times, and its Δ is back where it was.
to read it: link.go, Link.Step: a step adds sign × increment to one whole-number Δ, and nothing else.

two angles:
A rotation is a number of steps in φ and a number of steps in θ.
φ and θ are independent angles:
stepping one never changes the other.
Where a link points is decided by those two numbers alone.
So steps in φ and θ can be made in any order,
and the link ends up pointing the same way.
to see it: on one link step φ then θ, and read its start + Δ,
the read-only row showing where the link points;
step both back, then step θ then φ, and start + Δ is the same.
to read it: link.go, Link.Dir: start + Δ, one sum per angle;
frame.go, Frame.Vec: x, y, z made once, from those two sums.

moving nodes:
A link turns about the node it starts from.
Stepping a link moves the node at its end
to where that link now points.
The other links touching that node are remeasured
from where their two nodes now are,
so every link always describes where its two nodes really are.
to see it: step a link, and its end node moves while the links touching it follow.
to read it: peer_moves.go, Peer.take: the end node goes to the other node's place plus the link;
Peer.sat and Peer.moved: the other links are remeasured (link.go, Link.Remeasure).

the network:
A link can be selected: marked to be turned together with the other selected links.
One step rotates every selected link at once.
Each node moves on its own,
once it has heard where its neighbours are.
It refuses changes that cannot be:
a length below zero,
or a second selected link into the same node.
to see it: in sequence 1 press the both ▲, the button that steps every selected link,
and nodes 2 and 3 both move in one step.
to read it: peer_moves.go, Peer.stepAll, Peer.tell and Peer.recover: step, send the place, place from it;
peer.go, Peer.Ready: shown once every neighbour is heard;
Peer.stepR and peer_edits.go, Peer.press: a length below zero is refused;
peer_edits.go, Peer.pickReq: a second selected link is refused.

time:
Changes play out at a speed a person can watch,
and that speed is set from the UI.
Repeating two different rotations with different centres
makes the links swing like an arm on its joints.
to see it: keep repeating two rotations with different centres, and the links swing like an arm.
to read it: Categories/Clock/human_tick.go, HumanTick: every node counts ticks from one shared start.

sequences:
A scene holds several sequences.
Each sequence is a separate saved setup of nodes and links.
to see it: switch sequences, and each shows its own nodes and links.
to read it: Categories/Scene/Scenes/sequences.go, SequenceDir: one folder per sequence.

the screen:
The simulation writes out every place and link,
and the screen only draws them,
so what is on the screen is the simulation itself,
not a second copy of it that could disagree.
Node places and links are saved as they change,
so a scene reopens where it was left.
to see it: close and reopen the scene, and it is where it was left.
to read it: Categories/Node/nodefile_place.go, WritePlace, and link_files.go, WriteLinks:
one value per file, written by the node that owns it.
