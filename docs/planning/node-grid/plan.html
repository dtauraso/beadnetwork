Node grid · each node's data lives in that node's grid, and everything else reads it

The model

One grid per node. A node's grid holds all of that node's data: one column per step of the open sequence, one row per value. Nothing about the node is kept anywhere else.

  • Everything that is typed: each link's start, Δ, nΔ, 1 step for φ, θ and r, its lock, whether it is picked; the node's ref Δφ, Δθ; the sequence's s.
  • Every link: the links into the node and the links out of it.
  • Everything computed: the angle sums (start + Δ turned by the ref), the node's place (polar index and x, y, z), each out-edge's start and end points and its step count.

Everything reads the grid. The diagram, the Node grid tab, the Links tab and the Tree tab all get their values from the grids. None of them keeps its own copy, and none recomputes a value the grid already has.

A computed cell is a reference, not a second value. A sum cell is worked out from the grid's own start, Δ and ref cells, and stored back in the same grid, so the grid, the tabs and the diagram can never disagree.

The one repo rule it has to meet

CLAUDE.md: one writer per file, written by atomic rename, and the TS side only draws what Go wrote. So each grid file has exactly one writer, the node it belongs to, and the diagram reads values Go has already computed.

One node's grid

Columns are the steps of the open sequence. Rows are grouped: the node itself, then one band per link (in and out), then what is computed. Example for node 2 with one link in (1→2) and one out (2→3):

A link is in two grids: the out band of its source node and the in band of its target node.

On disk

  • One file per node per sequence: sequences/k/nodes/<id>/grid.bin, written by atomic rename like every other value file.
  • Laid out the way block files already are: the layout generator names the rows, and each row is a run over the steps (the f32Run/i32Run the angle pill already uses), so adding a step widens every run and adding a link adds a band.
  • A small header gives the step numbers and, per band, the link name and direction, so a reader knows which run is which without guessing.

Who writes

WriterWrites
the nodeits own grid.bin, every row in it, typed and computed. It is the only writer of that file.

Edits. When a value is typed in the Links tab or the Node grid tab, the edit goes to the node(s) whose grid has that cell, the way SetLink already goes to a node. The node sets the cell, recomputes the cells that refer to it (the sums, its place, its edge ends), and writes its grid. An edit to a link goes to both of its nodes, since both grids have it.

Order

Each step leaves the editor working, and is checked in the editor before the next one starts.

  1. The grid file. Its layout (rows, runs over steps, header) and the node writing it from the values it has now: typed rows from its links and ref, computed rows from its own math.
    Check: dump a node's grid.bin; its numbers match the Tree tab and the Node grid tab today.
  2. Node grid tab reads the grids. The tab draws each node's grid file as is, every row, every link in and out.
    Check: the tab shows the same numbers as before, plus the out-links and the positions.
  3. Edits go to the grid. Typing in the Links tab or the Node grid tab sends the edit to the node(s) owning the cell; the node writes its grid.
    Check: change a start in the Links tab, see the sum and the edge move in the grid tab and the diagram.
  4. Links tab and Tree tab read the grids. StepLinks, stepLinksTo and DirFrom in Builder are deleted.
    Check: every Links tab action from the UI standard still works.
  5. The diagram reads the grids. Node place and edge ends come from the shown step's column; those values leave node.bin and edge.bin.
    Check: drag a node and step through steps; the diagram and the grid tab show the same place.
  6. Old files go. Existing scenes are converted once into grid files; the per-step link files and the link folders are deleted.
    Check: topology-pair-phi-theta-3 opens with every sequence and step as before.

When it lands

MODEL.md and CLAUDE.md gain a line: a node's grid is its data and every view reads it. This plan is deleted.
