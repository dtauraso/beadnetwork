Timing-Window (Coincidence-Detection) Rule

branch: task/timing-window  ·  docs/planning/visual-editor/timing-window.md
Overview Diagram Rules Windows Tests

The timing-window rule applies to nodes with two or more input edges — coincidence detection is only meaningful across multiple inputs. A node with a single input edge has no window and receives normally (blocking Recv). A windowed node (≥2 input edges) collects one pulse from each of its input edges. If all of them arrive within window W of the first arrival, the combination is accepted and the node fires. If W elapses with any input still missing, all held inputs are discarded (via Done) without firing, and the node resets to wait for the next first-arrival.

The timing window opens when the first input arrives (t0).

This directly solves the permanent-delete case: an input edge removed for good means that input will never arrive, so the gate would block forever. With a timing window it times out after W, clears, and lets the ring keep running — no pile-up, no stall.

W is derived per-node from current input-edge geometry (W = 1.5 × max(simLatencyMs) over current input wires) and stored in node.data. It is recomputed automatically whenever an input edge's length changes.
