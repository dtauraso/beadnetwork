Timing-Window (Coincidence-Detection) Rule

branch: task/timing-window  ·  docs/planning/visual-editor/timing-window.md
Overview Diagram Rules Windows Tests
  • Window iff ≥2 input edges. The timing-window rule applies only to nodes with two or more input edges. A node with a single input edge has no window — it receives normally with a blocking Recv. The rule is stored per-node in node.data (same ownership as send rules).
  • Core rule: a windowed node (≥2 input edges) collects one pulse from each of its input edges. If ALL of them arrive within window W of the first arrival (t0) → ALL inputs are kept (the combination is accepted; the node fires). If W elapses with any input still missing → ALL inputs are removed (discarded via Done without firing); the node resets and waits for the next first-arrival.
  • Window opens at t0 — the wall-clock moment the first input arrives. W is real elapsed wall-clock time measured at the node.
  • W is derived, not stored — recomputed from the node's current input edges on every input-edge-length change (move, reconnect, midpoint drag): W = 1.5 × max(simLatencyMs) over current input wires, where simLatencyMs = arcLength ÷ 0.08 WU/ms. The value is a geometry snapshot, not fixed config.
  • Clear semantics — call Done on each held input's In port (drains the upstream wire so a consumeGated source's WaitConsumed returns). No Fire(). Emit a window-clear trace breadcrumb for observability.

Implementation note — windowed nodes use a non-blocking poll primitive (PollRecv() (value, ok) on PacedWire/Out) instead of a parking Recv, with a select-timeout or short sleep between iterations to avoid busy-spin. Single-input nodes keep their existing blocking Recv unchanged. inhibitRight0 is the first windowed node wired up.
