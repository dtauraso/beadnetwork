Links tab, redesigned φ,θ tab · a proposal with mockups
Proposal

Author a φ,θ sequence the way you think about it

The Links tab is where a sequence is built: which links move in which step, by how much, and in which direction. Today it is one long folding tree. This proposal turns it into a score: steps across, links down, every move visible at once, with a dial that shows each angle as a turn instead of a sum.

The proposed Links tab at a glance. The scope bar sits at the top, the score is on the left, and the inspector for the selected cell is on the right. The Layout page labels each region.

Six principles

1 · One scope at a time, always named

Frame, sequence and step are different scopes with different costs. A frame edit reloads the scene, so it should never sit one row away from a Δ press.

2 · Show the turn, not the arithmetic

An angle is 0–12 around a circle, which is a clock face. Draw it as one. "φ 3 + total 2 + 1 → tick 6" becomes a hand moving from 3 to 6.

3 · Steps side by side

A sequence is a set of steps applied in order. Showing them as columns lets you compare a link across every step without opening and closing folds.

4 · Prevent, don't refuse

The rules are known in advance: one picked link into a node, a shared increment, fixed radii. The UI should shape the input so a refusal can't happen, and say why in place.

5 · The scene is the preview

Selecting a step shows that step in the scene. Hovering a row lights that link's edge. Pressing Δ shows a ghost of where the node lands.

6 · Keyboard first, like a tracker

Arrows move between cells, +/− press Δ, and Space picks. The mouse works everywhere, but a whole step can be written without it.

Mental model

What a sequence is, as data

The redesign starts from the PhiTheta SPEC (Categories/NodeKinds/PhiTheta/SPEC.md), not from the tree. Laid out by scope, a sequence's content turns out to be a grid.

Scopes, from global to a single cell

Who edits what. Most edits happen in the bottom-right box: one step, one link. Today's tree makes that box the deepest thing to reach.

One link, one angle

start 3 grey arc from 0

Δ +4 blue arc, one dot per press (nΔ 1)

The hand points at 3 + 4 = 7, the direction the link's vector takes.

The SPEC defines an angle as a turn in 0..12, where 12 is 0. Past 6 it keeps going the same way, and a press steps up or down by the increment with no ends. That is a clock face, exactly. Everyone already reads clocks.

The scene already draws these arcs on each link (AngleArcs): from 0 to start, then each Δ tick. The dial draws the same arcs in the panel, so the panel and the scene can't disagree about what a number means.

"number × s" is still shown as small print (for example 7 × 4), because s changes the tick count but never the angle.

What happens on a step (StepAll)

The conclusion that drives the layout

The content of a sequence is a matrix: links down the side (grouped by the node they point into, because that is where the pick rule lives), steps across the top, and a small record in each cell. A matrix should be shown as a matrix. That is the Score.

The score

Like a music score or a tracker: time runs left to right, one row per voice. Here a voice is a link and time is the step list. You read a whole sequence at a glance and compare steps by looking sideways.

Panel and scene stay in sync

The scene is the preview. Hover and drag only draw ghosts; nothing is sent until a press or a release, so a ghost can't drift from the real place.

Because a press moves every node downstream (see Model), the ghost is drawn for the whole downstream chain, not just the target.

Ghost positions are computed in Go and written to a block file like every other position; the renderer draws them at reduced opacity.

Implementation

How it would be built

Nothing here changes the model or the bridge. Go still computes every rect and hit region and writes them to the sheet's block file; the TS only draws them. The work is new Sheet layout primitives and a new arrangement of the same Builder edits.

Ship order: each step stands alone

Step 2 can ship beside the current tree (a second view of the same data) so the old panel stays usable until the score can edit.

Verification

No tests, per the repo. Each step is checked by driving the editor on topology-phi-theta: sequence 2 for the small case and sequence 5 (6 nodes) for the dense one, comparing the scene before and after the same edits made in the old tree.

Risks

Ghost preview costComputing downstream places on hover means a StepAll dry run in Go. If it's slow, ghost only the target node.
Key collisions+/−/[/] may already mean zoom or camera. Gate them on the score having focus.
WidthThe panel is narrow by default; the drawer layout has to be good, not a fallback.
Nested stepsDeep nesting makes many sub-columns. Expand one level at a time.
