wirefold · node 1 fan-out · 1→2 and 1→3

Two loops, not one: where the consistent one-tick offset comes from

Node 1 places both beads in a single cycle. They still start one tick apart, every time, because a bead's start time is stamped when its wire is drained — and a different goroutine does the draining.

01 · who is running

Six goroutines touch this fan-out. The two wires are not among them.

Since the wire goroutine was removed, a PacedWire is a passive queue. Node 1's own mover steps both of its outgoing wires.

02 · the interleaving

The mover's pass lands between the two sends

Both goroutines sleep exactly one cycle, so their phase offset is stable. The mover walks its wires in a fixed order. Wire 1→3 is therefore drained just before its bead arrives — the same wire, every cycle.

the slice

Wire 1→3 is drained one instruction too early. Its bead is already on the way from the Input goroutine, but has not landed on inCh yet, so the drain finds an empty queue and moves on. The bead waits a full cycle and is stamped T+1.

  1. broadcastPlace pushes bead A onto wire 1→2's inCh.
  2. The mover's pass begins: it drains 1→2 and stamps bead A with placementTick = T.
  3. It drains 1→3 — empty. Bead B is microseconds away, but not there.
  4. broadcastPlace pushes bead B onto wire 1→3's inCh.
  5. Next cycle, the mover drains 1→3 and stamps bead B with placementTick = T+1.

03 · why it is the same every time

Nothing here is random

Three things are fixed, so the outcome is fixed. Both loops wait one cycle, so their phase relationship persists rather than drifting. The mover always visits its wires in the same order. And broadcastPlace always sends in the same port order. A race with a stable phase is not a flake — it is a schedule.

The wire order itself was fixed at load time, but which wire ended up first depends on map iteration during bind, so which of the two edges lags can differ between runs, while staying constant within one run.

04 · the fix

Stamp the tick where the decision happens

A bead's start time should be when the node sent it, not when a wire was next looked at. Move the stamp into Send, on the sending node's own clock reading, and have drainPlacements use the tick the request carries. Two beads broadcast in one cycle then share a placementTick no matter which wire drains first.

The current drain-time stamp was correct while each wire had its own goroutine — the placeRequest comment still cites that reason. Removing the wire goroutine invalidated it and left the stamp behind.
