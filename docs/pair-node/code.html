One count, taken at the end the arrival is nearer

The measurement

nearerEndCount returns the count, and which end it came from

u = (t − a) mod points

u < h : c = u, the top is the nearer end

u ≥ h : c = (b − a) mod points, the bottom is

c lives on a ring of h, not of points. A node draws two ends and they differ by exactly h, so one of the two counts is always under h — and that one is already the acute angle at its own end

the bottom's count is taken from the bottom's own state, a link the ring resolved, rather than by folding h back out of u

this replaced angleLength, which folds points down to h with an absolute value and so cannot say which end it measured. The rule needs that end: it is the one the update moves

A mode is one row of numbers, and the rule never reads which row

The per-mode data

stoppingCounts the counts a mode stops at

perpendicular { 0 }

parallel { q }

setting every count

perpendicular used to carry TWO resting lengths, { 0, h }, because measured from the top its two stopping tilts fall on opposite ends of one line. Counted from the NEARER end they are the same count, so the row is a single 0 — the pair was one fact written twice

setting stops everywhere, so it is at rest wherever it stands and the turn below is never reached. It is a row like the other two, not an exemption from the rule

machineFor refuses a mode with no row rather than defaulting to an arrangement

Two distances, and the smaller one is the answer to both questions

The turn

walk how far the stop is, each way round the count-ring

up = (stop − c) mod h

down = (c − stop) mod h

and the two questions one arrival asks

fromRest = min(up, down)

settled = fromRest = 0

step = the measured end moves one slot up if up ≤ down, else down

the comparison is between the two ways round from where the node IS, not between two places it could go. The rule used to redo the whole measurement at both neighbours and compare the results — picking the better of its next two positions without ever working out where it was heading

no value here is negative and no sign is taken. up and down are counts of slots; the direction is which is smaller

the tie goes UP, and it is load-bearing: ≤ written as < picks the wrong state, first at t = 0 with a = 0, on both lattices

nothing here asks which mode is running. arith.html prints this as two four-line blocks, one per arrangement, and they are one sentence said twice — walk the count the short way to your own stop. Written as two blocks, this file would have a switch in it

The end that was measured is the end that moves

The write

Top and Bottom are both stored

setTop(x) : Top = x, Bottom = x.opposite

setBottom(x) : Bottom = x, Top = x.opposite

these are the ONLY ways either end is written, and each writes BOTH — the end named, and the other read off its opposite link in the same statement. The two cannot come apart because coming apart is not spellable, not because a rule says not to

with only the top stored, the half of the ring measured at the bottom had to be written back to the top with its direction negated — a correction term standing in for a fact the state could not say

nothing about persistence changes: position.json still carries one angle, and the second end is still a half turn from it

The checks

TestOneRoundIsSignAndRemainder derives arith.html's forms and asks the machine for the same answer, on every (tilt, arrival) pair of the 24- and 48-point lattices

TestAnUpdateDrivesTheEndItMeasured the driven end is the measured end, and the two ends stay a half turn apart

TestAModeHaltsExactlyOnItsHomeSet settled agrees with the mode's own row, so a row and the rule cannot drift apart
