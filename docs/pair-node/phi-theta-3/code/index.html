The code behind these tabs

How the three-node card, the a→b vectors, the a→b builder, the a→b tree and the builder tests are built: which page loads which scripts, which of the builder's files uses which, how a page starts from the saved sequences, and how one edit travels from a button to sequences.js and back into the tree tab. Every page is plain scripts with no build step; a script's names are globals the scripts after it can use, so a page's script order is its dependency order.

1. Pages and the scripts they load

Each column is one tab. A box sits in every column it spans, so a box across several columns is a script those tabs share. The builder, the tree and the tests all run the same builder model; only the builder and the tree read the saved sequences.

2. Inside the builder: which file uses which

A file uses only files in rows below it; "uses" names the files whose functions it calls. The bottom row uses nothing. builder.js is the page: it is the only file that runs on its own, and every other file is functions it calls.

  • builder.js — setup() builds the panels from the builder's data, update() runs the ticked methods, draws the canvas and saves; the canvas's look-round, pan and zoom.
  • panel-lists.js — the step list, each step's nodes table, the read-only start and start + Δ list, and the nodes' places in O's frame.
  • panel-edges.js — picking edges, each picked edge's Δφ and Δθ step, and move all.
  • panel-seqs.js — the sequence picker, new and delete sequence, undo.
  • preset.js — the three-node example.
  • move.js — placing an edge's second node from its first, re-measuring the other edges at a moved node, setting a start, changing a node's s.
  • methods.js — the two methods you tick, the a→b card and the pair card, as steps to list and draw.
  • draw.js — the diagram's axes, each edge's line with its arrow, and the φ and θ arcs.
  • save.js — reading sequences.js into a builder, packing it back to text, the undo list, sending it to the docs server.
  • direction.js — an edge's direction (start + Δ, wrapped into one turn), measuring a direction from two node places, the lines and arcs to draw.
  • place.js — a node's place from its scene index and back, and an edge's vector from φ, θ and r.
  • vec.js — adding, subtracting and measuring vectors, polar to x y z, wrapping a number into one turn.
  • graph.js — linking an edge to its two nodes, dropping edges and nodes, the open step, the nodes shown.
  • text.js — numbers, points and indexes as text.

3. Starting a page

The builder and the tree read the saved sequences as a script, not a request: sequences.js is a line of JavaScript that sets window.B_SAVED. The VS Code extension writes port.js when it starts, so a page knows where to send saves and which token to send with them.

The builder object is the tree the a→b tree tab draws. bWire turns each saved edge's from and to names into the node objects themselves and links each edge into its nodes' in and out lists, so moving a node is seen by every edge that touches it. With no saved file the builder starts from preset.js.

4. One edit, from the button to the tree tab

Pressing + under move all, top to bottom. Each column is a file or a process; an arrow is a call, a loop is work inside one file. The page saves after every redraw, so every change reaches sequences.js; nothing waits for the save.

  1. The + is drawn by bEdgePicker.
  2. Δ wraps into one turn, so below 0 it comes back in at 12s and counts down.
  3. bMoveAll takes every picked edge at once.
  4. bPut sets the second node at its first node's place + the edge's vector; then bRemeasure measures every unpicked edge at a moved node from the two node places. A picked edge is never re-measured, so + then − returns every edge.
  5. changed() is setup() then update() in builder.js.
  6. The canvas, the panels and the step lists are all redrawn from the builder's data; nothing on screen is kept between redraws.
  7. bKeep is called at the end of every update().
  8. The undo list holds the last 100 states; undo loads one back through bWire.
  9. bSend posts the whole file with the token from port.js, and only when the state changed. It does not wait for an answer before the next edit.
  10. saveDoc writes only a file named sequences.js under docs/pair-node, to a .tmp first and then renames it over, so a reader never sees half a file.
  11. tReread loads sequences.js again as a script every second.
  12. The tree redraws only when B_SAVED differs from the last read. The builder does not reread the file: an open builder tab keeps its own copy, and its next save writes over the file.
