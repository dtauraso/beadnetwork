The code behind the builder and the tree

Function by function. Each box is one function: its name, what it does, and the file it lives in. An arrow goes from a function to a function it calls. Read each map left to right, from where it starts.

1. Opening the builder

The page reads the saved sequences, or starts from the three-node example when there are none, then builds the panels with setup and draws with update.

2. update: after every change

update runs the ticked methods, paints the canvas and saves. It runs after every edit.

3. setup: the panels and what their controls call

setup rebuilds every panel. A control's edit calls the function it points to, then setup and update again.

4. Moving a node

A move is a request. Dashed boxes are a node's own methods, in node.js: each node keeps its own place, its s, and its out edges' start and Δ. The edge's first node sends: it works out its place plus the edge's vector, and the second node takes that as its place. The moved node then re-measures its own out edges and tells the first node of each in edge, which re-measures that edge from the two places.

5. The methods' steps and the edge drawing

The two methods and the diagram's arrows and arcs all work from each edge's direction, start + Δ.

6. Saving, and the tree tab reading it back

bSend posts the file to the docs server in the VS Code extension. The tree tab reloads sequences.js every second and redraws when it changed.

7. The tree tab

tDraw loads the builder with the builder's own bLoad, then lays out one box per field, edge and node.
