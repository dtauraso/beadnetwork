The a→b tree

Editing a→b, by the pairs each part of the move uses, and the builder function that does each part (builder/builder-send.js). The pictures use the three-node example: a→b φ 2 θ 0 r 2, b→c φ 4 θ 0 r 2, a→c a copy, then a→b's φ set from 2 to 3.

root — bMove(st, a→b, was)

One call per a→b edit. It runs (a→b, a→c) first, which hands back each copy row whose c moved and the turn it moved by, then runs b→c once for each of those.

a→b — bHead(st, a→b)

b goes to a + the a→b row's frame × (φ, θ, r). Setting φ from 2 to 3 swings b round a by one tick, 30° here (12 ticks a turn, s = 1).

(a→b, a→c) — bPair building rot with bStep and bRot

The turn is read off a→b: whatever turned a→b from was to now is rot. With a→c's own step on, rot is built from was to was + sign(change) × step instead, per φ and θ.

a→c — bRound(st, a→c, rot)

c = a + rot × (c − a). c moves on a circle round a, so |ac| stays the same. Only c moves here; b was already placed by a→b. If a or c has no position, nothing moves and b→c is skipped.

b→c — bTurnVia(st, a→c, rot)

The row that placed c, here b→c, keeps its φ 4, θ 0, r 2 and has its frame turned by rot instead. Read in the unturned frame, b→c now points at φ 5; in its turned frame it still reads φ 4, so the next time b→c places c it puts c where bRound did.
