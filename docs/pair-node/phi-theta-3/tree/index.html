The a→b tree

The a→b builder's data as it is now, drawn as the tree the builder keeps: builder, then the sequence open in the builder, then that sequence's steps, one box each (each step holds its picked edges, which all leave one start node, the locks that move them together, and — worked out, not stored — the edges left for vector recalculation); under each step its method cards (the item the cards run on, the ticked methods and the card step) and its edges (each with its increment and its lock), one box each; then the step's nodes, under the edges that join them (a node no edge joins hangs from its step); each kind of box has its own outline colour; each box holding that thing's variables. The builder stores its data in this same shape: builder, its sequences, each sequence's steps, each step's edges and nodes. Read with the builder's own scripts from builder/sequences.js, the file the builder writes on every change; it redraws when that file changes. Stored values are plain; values the builder works out from them are not stored: they sit below a dashed line in each box (an edge's start + Δ, then “measured C_a → C_b”, the direction from its first node's drawn place C to its second's, taken at the first node — when the two differ, the edge's settings and the diagram disagree), in italics, and a value that is a reference to another box — a node or an edge, not a copy of it — is green and dotted-underlined.
