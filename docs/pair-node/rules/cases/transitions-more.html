What the gap read actually asks

arrival lands at count the two tilts are mode chosen
c = 0 — on this node's tilt line, either end a quarter turn apart — ALREADY perpendicular. The code measures this the other way about, as the gap between the two TILTS being a quarter turn (machineForGap); the two are the same fact, since the arrival is the partner's normal perpendicular
anything else an acute gap parallel
The two rows are perpendicular's gap and everything else, which is the honest reading of the rule: it asks "is this setup already perpendicular?", and everything that is not becomes a parallel pair to be closed. A pair set up at a quarter turn is therefore perpendicular and finished on arrival — it has nowhere to walk.

The cases that are NOT mode cases

case what happens, and why it is not a fourth mode source
the lattice changes under a running mode the stopping count is read from the ring at every call, never stored, so a mode that stopped at 12 on a 48-ring stops at 6 on a 24-ring with nothing to migrate. The INDEX is what survives, not the angle adoptLattice
the arrival lands on this node's own top the exchange comes to rest: nothing is sent and no bead is placed. That is the halt of the EXCHANGE, not of a mode handleVectorCycle
the partner's arrow is reversed not a case at all — the count is taken from whichever END is nearer, so a reversed partner lands exactly where an aligned one does and parallel reads both as its one stopping count nearerEndCount
