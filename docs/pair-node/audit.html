Why this audit exists

The two machines were split into two files so each could be BUILT and changed without the other moving. That worked and is not in question here. What this reports is the separate question of how much of the two is actually different, now that both are finished — 103 lines across the two files, of which the genuinely distinct part is one line.

Nothing here is a proposal. Merging them back is exactly what the split exists to prevent, and a duplicate that is deliberate is not a defect.

1 — The two misses are complements. This is exact.

Written for a separation already folded into [0, half], with half = 2·quarter:

parallel miss = |sep − quarter| parallel.go
perpendicular miss = min(sep, half − sep) perpendicular.go
perpendicular miss = quarter − parallel miss everywhere on the ring, no exceptions

Proof, both halves of the fold. If sep ≤ quarter then |sep − quarter| = quarter − sep, so quarter − |sep − quarter| = sep; and min(sep, half − sep) = sep, since sep ≤ quarter ≤ half − sep. If sep ≥ quarter then |sep − quarter| = sep − quarter, so quarter − |sep − quarter| = half − sep; and min(sep, half − sep) = half − sep. Equal in both cases.

sep (on a 48-point ring, quarter = 12) parallel miss perpendicular miss sum
0 12 0 12
5 7 5 12
12 0 12 12
20 8 4 12
24 12 0 12

CONSEQUENCE: minimising one miss is maximising the other. The two step functions are the same walk run in opposite directions on one number — not two rules that happen to resemble each other.

2 — step is character-for-character identical

if m.miss(from.next, arrival) <= m.miss(from.prev, arrival) { return from.next }; return from.prev perpendicular.go
if m.miss(from.next, arrival) <= m.miss(from.prev, arrival) { return from.next }; return from.prev parallel.go

Same text, same tie-break, differing only in which miss the receiver resolves to. Six lines each.

3 — halted is one predicate written two ways

sep == 0 || sep == half ⟺ perpendicular miss == 0 perpendicular.go
sep == quarter ⟺ parallel miss == 0 parallel.go

Neither says anything miss == 0 does not already say. Both are a second spelling of their own miss being zero, and the caller only ever asks whether the node is home.

4 — choice and String are mirrored boilerplate

String() → its own name choice() → its own Wiring.TiltMachine constant

Two lines each, identical in shape, carrying nothing but the machine's own identity.

What is actually different

ONE THING: which separations count as home. Perpendicular has two of them — nothing, and a half turn — and parallel has one, a quarter turn. Everything above follows from that and nothing else. Stated as data rather than as code, the whole difference is:

perpendicular home = { 0, half }
parallel home = { quarter }

The two sets are not arbitrary either: quarter is the midpoint of 0 and half, which is why the misses sum to a constant and why each machine's home is the other's farthest point.

What the split still buys, given all that

A change to one file cannot move the other, which is the property it was built for and the one that was repeatedly lost when the two shared a parameterised function. That property does not require the two to be independent — and they are not independent, since one miss determines the other — it requires only that no edit reaches across.

The header in perpendicular.go claims they share no computation. That is true of the TEXT and false of the MATHEMATICS, and this page is the correction to it.
