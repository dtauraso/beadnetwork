Machine sameness audit

where perpendicular.go and parallel.go were the same thing — the report that folded them into one machine

The finding, in one picture

One curve is the other upside down. Minimising one miss IS maximising the other, so the two machines are one walk run in opposite directions on one number — not two rules that happen to resemble each other.

Exact, both halves of the fold

case parallel miss quarter − that perpendicular miss

sep ≥ quarter sep − quarter half − sep half − sep
Equal in both cases, so equal everywhere on the ring. No exceptions, no approximation.

What is actually different: which separations count as home

Filled is home, hollow is farthest. Perpendicular's home is exactly parallel's farthest point and the reverse, because quarter is the midpoint of 0 and half — which is why those two misses sum to a constant.

SETTING is the third mode: a node that has not yet decided which of the two it runs. Its home is every separation, so it is already at rest wherever it stands and no arrival moves it — which is what "still being set up" means, said as a home set rather than as an exemption from the rule.

One walk, two directions

Same number, same step, same tie-break — opposite downhill. The green points are the halts: whichever machine is running, it is heading for one of them.

103 lines, and where they go

step is character-for-character identical, differing only in which miss the receiver resolves to. halted is each machine restating its own miss being zero. String and choice carry nothing but the machine's own identity.

What was done about it

This page was written as a report, not a proposal — the split existed so a change to one file could not move the other, and that property was repeatedly lost when the two shared a parameterised function.

The two are now ONE machine (nodes/Node1/machine.go), because of what is measured above: the difference is DATA, not code. A mode contributes a home set and nothing else. The three earlier attempts each parameterised the RULE — a branch inside miss, a mode passed to step — and that branch is what let a change meant for one mode land in the other. There is no such branch now: miss is a minimum over a set of numbers and cannot ask which mode it serves, and step never sees a mode at all.

The claim the old perpendicular.go header made — that the two share no computation — was true of the TEXT and false of the MATHEMATICS. That is what this page corrected, and the fold is what followed from it.
