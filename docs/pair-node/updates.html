The numbers

Top the tilt — a STATE on a ring of 24, not a number a node adds to. Turning is following a link, Top ← Top.next or Top ← Top.prev, never +1 or −1 with a wrap. Top.idx is that state's own index, 0…23, and is what leaves this kind: onto the wire, into position.json, and 15°·idx is its angle from world +y
r, and whether r is set the last direction received — the third drawn arrow
6 · 12 · 24 a quarter turn · a half turn · a full turn, counted in those steps
one step = 15° = 0.2617993877991494 rad the one quantum; every angle streamed is an index times this

The machine — 24 states, and every input is a transition

input transition
arrival IS this node's own machine's halt stay — and this is the halt: reply anyway, no bead placed
arrival is not this node's own machine's halt Top ← this machine's step(before, arrival) — next or prev, whichever lands closer to its own halt
no machine yet (before START, or after RESET) stay — nothing chooses a machine from an arrival
panel ▲ · panel ▼ Top ← Top.next · Top ← Top.prev — moves the tilt only, chooses no machine
RESET, from the button or the marker Top ← ring[0] · Machine ← nil
START on id 1 · a bead on In stay — START sends from where it already is, a bead only paces
Those six are every input the machine has, and the four transitions are every move it can make. A state is a direction the tilt can point, so there are 24 of them and the tilt is always exactly one — there is no 25th to reach and no value between two, which is what makes an off-the-ring tilt impossible to write down rather than merely guarded against.
The seam at 23 → 0 is one link like any other. Nothing detects it, nothing corrects for it, and no rule mentions it — the ring closes because the last state's next IS the first, fixed once when it was built.

The three directions a node reads off its own state

direction both nodes of a pair — same unmodified rule
top — the tilt itself top = Top
bottom — half a turn from the top bottom = Top.opposite
coplanar normal — a quarter turn from the top normal = Top.quarter
what it sends — the normal, unchanged sends = normal
opposite and quarter are links resolved once when the ring is built (init, in ring.go) — a field read, not a sum. Both nodes of a pair run this same unmodified rule — there is no per-node sign.
There is nothing to wrap: a link always points at one of the 24 states, so bottom and normal land on the ring the same way top does, by construction, with no comparison and no reduction at either one.

separation — what decides both machines

sep = |a.idx − b.idx|, folded to ≤ 12 how far apart two directions are on the ring, the SHORT way round. Both sit on 0…23, so this is an exact integer, never more than a half turn
perpendicular's halt: sep ∈ {0, 12} the arrival sits exactly on this node's own top, or exactly on its bottom
parallel's halt: sep = 6 the arrival sits exactly on this node's own coplanar normal
anything else an ordinary separation to whichever machine this node holds — one step closer, next or prev
Integer steps, so separation is exact: no float dot product, and no epsilon band to tune. A separation of 6 is perpendicular's ordinary angle on the way through and parallel's halt; a separation of 0 or 12 is the reverse. Which one a node HALTS on is read once, at START, from the gap between the two tilts (machineForGap) — see Perpendicular.

Before the loop

TryEmit(EmitGeometry) nothing — the builder leaves that callback nil for this kind

every cycle, after the three above then
Self.Step(ctx, T) drain extIn and every neighborIn until both are empty · DriveOneCycle(T) on each outgoing wire · flushPending() · write one frame
SpeedCh holds a value clk.SetSpeed(that value); depth 1, latest wins. Empty: no call. Never blocks

One quarter-turn link from top to normal, one half-turn link from top to bottom, at every state on the ring, no exception — bottom.idx and normal.idx are field reads, resolved when the ring was built, never a sum computed here. Both nodes of a pair run this same unmodified rule.

A run, from START to the halt

event machine · separation result
node 1 top.idx = 23, node 2 top.idx = 10 · START — node 1 sends normal(23) = 5, places a bead. Neither node has a machine yet
node 2 receives 5 — its FIRST arrival machineForGap: back the quarter out of 5 (→ partner tilt 23), sep(10, 23) = 11 — not a quarter turn, so PARALLEL. Then sep(top 10, arrival 5) = 5, not parallel's halt (6) adopts parallel · Top ← Top.next, top.idx 10 → 11 (parallel's halt is one step away) · sends normal(11) = 17, carrying Machine=parallel · bead
node 1 receives 17 adopts PARALLEL from the message (adoptMachine), before reading any gap itself · sep(top 23, arrival 17) = 6 — parallel's own halt HALT on parallel. Top unchanged, no send, no bead
at rest top.idx = 23 on node 1, top.idx = 11 on node 2 — both running parallel r = 17 on node 1, r = 5 on node 2 — the third arrows stay drawn
One send, one bead, and a single reply that lands on parallel's halt — same rule run unmodified on both nodes, once each has adopted the same machine. Sends and beads are equal in number because the only PlaceDrivenAt call sits in the same branch as the send, so no bead is placed on the halt.

What a report puts on this node's own frame

tilt angle = top.idx × 15° persisted
bottom angle = top.opposite.idx × 15° read off the link on every report, never stored
normal angle = top.quarter.idx × 15° read off the link on every report, never stored
received angle = r × 15° drawn only when set. Written to no file — a reload starts with r unset
the tilt's drawn length the node's radius when it stands upright with exactly one neighbour, otherwise 0
centre, reach, pole, ring axis unchanged by a tilt — turning is a step to a different state, and the separation stays where the last drag put it
the row it claims its own, or it panics — the row is an ownership claim, and a foreign node belongs in the target column
Every angle on the frame is an index times 15°, on this node's own dedicated pipe. Trig happens only where polar meets cartesian, never here.

What a reset puts back

Top ← ring[0], reported the bottom and the normal follow, being links off the new Top
r ← 0, set ← false, reported the third arrow goes away
VectorIn emptied depth 1, latest wins, so one receive empties it. A direction left sitting there arrives next cycle and steps Top straight back off ring[0]
In drained until empty beads already delivered here. Bounded by what the partner placed before it stopped placing
outgoing beads dropped the ones still crossing, dropped through this node's own self, which drives that wire
each node clears twice the button clears this node and sends the marker, after which it places nothing ever again; the partner clears when the marker arrives. That second clear is ordered after the last bead the sender could have placed, so it is the one that lands last
