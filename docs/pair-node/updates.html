The numbers

t the tilt index — the only number a node holds, and always on 0…23. One step is 15°, so t is a position 15°·t round from world +y, not a running count of clicks: step past 23 and it is 0 again, step below 0 and it is 23
r, and whether r is set the last direction received — the third drawn arrow
6 · 12 · 24 a quarter turn · a half turn · a full turn, counted in those steps
one step = 15° = 0.2617993877991494 rad the one quantum; every angle streamed is an index times this

The three directions a node computes from t

direction both nodes of a pair — same unmodified rule
top — the tilt itself top = t
bottom — half a turn from the top bottom = t + 12
coplanar normal — a quarter turn from the top normal = t + 6; if normal ≥ 24 then normal −= 24
what it sends — the normal, unchanged sends = normal
t + 12 draws the same direction whether t is positive or negative, since ±180° in θ is one place. Both nodes of a pair run this same unmodified addition — there is no per-node sign.
The wrap is one comparison, not a division: add 6 and pull back a full turn if that pushes past 23. Only the normal wraps this way — the bottom is t + 12 exactly, unwrapped, because the renderer decodes an index as (sin θ, cos θ, 0) and has no pole to cross.

The test that decides everything

d(a, b) = a − b, and + 24 when that is negative how far apart two directions are, in steps, on 0…23. Every index in the model is already on the circle, so a difference is within one turn either way and one comparison is the whole reduction — no %, and so no sign convention to get wrong
acute: d ∈ {0…5, 19…23} under 90° apart — the node turns
perpendicular: d ∈ {6, 18} exactly 90°, not acute — this is the halt
obtuse: d ∈ {7…17} neither test fires either
Integer steps, so d is exact: no float dot product, and no epsilon band around 90° to tune. Both tests fail together whenever d(v, top) is 6 or 18. Both passing is impossible: top and bottom are 12 apart, and each acute range spans 5 steps either side of the direction it tests.

One quarter turn at every index, no exception. Every value here is on 0…23, including the bottom: an index that would land past 23 comes back a full turn, one past the bottom of the range goes up one. Both nodes of a pair run this same unmodified arithmetic.

A run, from one click to the halt

event the two tests result
node 1 at t = 23, node 2 at t = 10 · START — node 1 sends normal(23) = 5, places a bead
node 2 receives 5 d(5, top 10) = 19 acute t ← 10 + 1 = 11 · sends normal(11) = 17 · bead
node 1 receives 17 d(17, top 23) = 18 perpendicular · d(17, bottom 11) = 6 perpendicular both perpendicular — HALT. t unchanged, no send, no bead
at rest t = 23 on node 1, t = 11 on node 2 r = 17 on node 1, r = 5 on node 2 — the third arrows stay drawn
One send, one bead, and a single reply that lands on perpendicular for both tests at once — same rule run unmodified on both nodes. Sends and beads are equal in number because the only PlaceDrivenAt call sits in the same branch as the send, so no bead is placed on the halt.

What a report puts on this node's own frame

tilt angle = t × 15° persisted
bottom angle = bottom × 15° recomputed from t on every report, never stored
normal angle = normal × 15° recomputed from t on every report, never stored
received angle = r × 15° drawn only when set. Written to no file — a reload starts with r unset
the tilt's drawn length the node's radius when it stands upright with exactly one neighbour, otherwise 0
centre, reach, pole, ring axis unchanged by t — a tilt turns an angle, and the separation stays where the last drag put it
the row it claims its own, or it panics — the row is an ownership claim, and a foreign node belongs in the target column
Every angle on the frame is an index times 15°, on this node's own dedicated pipe. Trig happens only where polar meets cartesian, never here.

What a reset puts back

t ← 0, reported the bottom and the normal follow, being computed from t
r ← 0, set ← false, reported the third arrow goes away
VectorIn emptied depth 1, latest wins, so one receive empties it. A direction left sitting there arrives next cycle and steps t straight back off 0
In drained until empty beads already delivered here. Bounded by what the partner placed before it stopped placing
outgoing beads dropped the ones still crossing, dropped through this node's own self, which drives that wire
each node clears twice the button clears this node and sends the marker, after which it places nothing ever again; the partner clears when the marker arrives. That second clear is ordered after the last bead the sender could have placed, so it is the one that lands last
