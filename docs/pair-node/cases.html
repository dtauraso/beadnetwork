The whole case space

A node's tilt machine is ONE instance (tiltMachine) whose entire state is which mode it is in. So the cases are: three modes, each against every ANGLE LENGTH an arrival can produce — the number of ring slots between this node's tilt and the arrival, counted the short way round. That is the grid below, on a 24-point ring where a quarter turn is 6 and a half turn is 12. Nothing else is a case: the turn never sees which mode is running, and there is no fourth input.

Read a row and you have that mode entirely. SETTING rests at every length, which is why a node being set up cannot be moved by an arrival. The other two rest at their own lengths and turn straight over the other's — perpendicular walks through a quarter turn, parallel walks through 0 and a half turn.

The two ties, and which way they break

case why it is a tie what happens
perpendicular, L = a quarter turn exactly between the resting lengths 0 and a half — both 6 away on a 24-ring turns UP
parallel, L = 0 or a half turn its one resting length is a quarter away in either direction turns UP
Both fall out of one <= in step: when the two neighbours are equally far from resting, the up bit wins. It is a convention, not a measurement — there is no better answer, since the two directions are genuinely the same distance. What matters is that it MOVES: standing still at a tie is the freeze the old "not acute" test produced.

Every transition — there are four, and no others

from → to what causes it source
setting → perpendicular first arrival, and the gap between the two TILTS is a quarter turn machineForGap
setting → parallel first arrival, and the gap is anything else machineForGap
setting → either the partner already chose and its reply carries the choice adoptMachine
perpendicular or parallel → setting RESET, and nothing else clear
There is NO perpendicular ↔ parallel edge. A chosen mode STICKS: a second choice — a click landing mid-run, or the partner's own answer arriving after this end already decided — is ignored, because re-deciding on a jitter is what once switched a started perpendicular pair to parallel one step after START.

What the gap read actually asks

arrival lands at angle length the two tilts are mode chosen
0, or a half turn a quarter turn apart — ALREADY perpendicular perpendicular
anything else an acute gap parallel
The two rows are perpendicular's resting lengths and everything else, which is the honest reading of the rule: it asks "is this setup already perpendicular?", and everything that is not becomes a parallel pair to be closed. A pair set up at a quarter turn is therefore perpendicular and finished on arrival — it has nowhere to walk.
