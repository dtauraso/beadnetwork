RESOLVED — task/mutex-debounced-persister deleted the debounce timer (and its lock) outright rather than keeping it: see docs/concurrency/debounced-persister-architecture.html for the full analysis. Every domain persister below now writes synchronously on the calling goroutine; there is no timer goroutine left to race. This section is kept as the historical record of why the lock existed.

the standard library's timer-fire API used to run every debounced flush in a new goroutine. That was the easily-missed racer against a drag-time synchronous write on the same file.
